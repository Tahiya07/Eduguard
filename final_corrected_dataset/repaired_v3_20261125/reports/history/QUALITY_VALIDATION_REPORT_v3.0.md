## Rules each rewrite followed

1. **OBE format.** Each rewrite is an instruction, not a question: no `?` and no wh-opening (What/Why/How/Which…). One sentence starts with an action verb from the target level's bank (`work/obe_verb_bank.json`, taken from `experiments/multitask_bloom_rewrite/prompts.py`). A scenario sentence may come first, provided an instruction sentence starting with a bank verb follows it.
2. **Bloom alignment by cognitive operation, not by verb.** Remember asks for recall only and never contains its answer. Understand asks for explanation, description, interpretation or illustration. Apply asks to carry out a procedure on a stated case. Analyze asks about relationships, causes, structure or attribution. Evaluate asks for a judgement against criteria or evidence. Create asks for a new product, plan or design.
3. **Content preservation.** Each rewrite keeps the source's subject, entities and data. It may not add new numbers: every number must already appear in that example's source or transformations. Six exceptions were reviewed individually; each is a method constant or device name, such as Simpson's rule weights 1, 4, 1. No new facts, criteria or attachments were added.
4. **Deliberately false claims.** The 59 exported Evaluate rows that contain a deliberately false claim keep every stated value (checked automatically). They stay marked `claim_under_evaluation.is_ground_truth = false`.
5. **No templates.** Verbs within each level were deliberately varied. Verbs that appear in more than one bank (Determine, Identify, Establish, Relate, Infer, Model) were used at each of those levels where the operation differed. There were no quotas and no mechanical substitution.

### Disputed source labels

- **252 (Analyze → Understand).** The source asks how a transaction processing system captures, processes and stores sales transactions. That is a process description, with no demand to relate parts, find causes, weigh evidence or examine assumptions. Its old Understand row was the source with only the verb changed. The label was corrected and the prior label is kept in `source_bloom_level_before_correction`. The Understand row was removed and a new Analyze row was written (how a failure in capture propagates to processing and storage). Split and group are unchanged.
- **157 (kept as Analyze).** The source asks how cultural, social, personal and psychological factors *influence* a purchase decision for a specified product. That is attribution of influence, which is Analyze. Its Understand row was rewritten as a description with an example of each factor, so the two levels no longer differ only by verb.

### Structurally similar Understand–Analyze pairs

The earlier audit's similar pairs were reviewed individually. Pairs that differed only by their verb were rewritten so the operations differ: Understand describes, paraphrases or illustrates; Analyze decomposes, traces, attributes or relates. Using the audit's content-token measure, Understand–Analyze transformation pairs with Jaccard ≥ 0.7 fell from 10 to 0, and near-identical pairs at any level fell from 69 to 36. The simpler whole-text measure gives 26 → 15. The 15 that remain were read and require different operations, for example describing each building versus comparing them.

## Diagnostics: can the level be predicted from the verb alone?

All numbers come from training on the train split and scoring validation + test (585 rows), using the same frozen splits for v2 and v3. These are diagnostics only. Wording was never tuned to lower them.

| Predictor | v2 | v3 |
|---|---|---|
| Leading verb only (majority level per verb) | 0.974 | **0.949** |
| First word only | 0.954 | 0.939 |
| Naive Bayes, full question | 0.947 | 0.906 |
| Naive Bayes, leading verb masked | 0.749 | 0.723 |
| H(level \| verb), bits (higher = verb less decisive) | 0.078 | 0.136 |
| H(verb \| level), bits (higher = more varied verbs per level) | 1.63 | 2.95 |
| Distinct leading verbs in train | 66 | 107 |

Verb diversity within each level (audit instrument with extended lexicon, all splits):

| Level | Top verb share v2 → v3 | Effective number of verbs v2 → v3 | Top-5 opening trigram share v2 → v3 |
|---|---|---|---|
| Remember | 0.36 → 0.28 | 3.7 → 6.7 | 0.08 → 0.08 |
| Understand | 0.93 → 0.48 | 1.4 → 5.4 | 0.38 → 0.25 |
| Apply | 0.25 → 0.26 | 11.4 → 7.7 | 0.12 → 0.09 |
| Analyze | 0.89 → 0.28 | 1.8 → 10.5 | 0.51 → 0.24 |
| Evaluate | 0.47 → 0.25 | 2.9 → 12.7 | 0.59 → 0.32 |
| Create | 0.49 → 0.43 | 3.5 → 7.3 | 0.07 → 0.06 |

Apply's effective verb count fell because v2's Apply rows included verbs from other levels and leading clauses ("Given", "Classify", "Identify", "Select" and others). Requiring OBE level-bank verbs removed those.

**What this means.** Verb variety within each level is now much higher, and the "Explain/Examine/Verify" templates are gone. The verb alone, however, still predicts the level about 95% of the time. This is built into the requirement that every row start with a level-specific OBE verb: apart from the few verbs that more than one bank shares, a verb maps to one level. **The dataset alone therefore cannot stop a model from learning the verb shortcut.** That has to be measured on the challenge set, using its `verb_shortcut_misleads`, `verb_multi_level_in_train`, `rare_or_unseen_verb` and `scenario_first` slices and the same-content adjacent-level pairs. A model meets the acceptance criterion only if its accuracy on those slices stays close to its overall accuracy.

The audit instrument's lexicon was extended for verbs the repair introduced (Indicate, Reproduce, Validate, Substantiate, Architect, Synthesize…) and for the cue word "supplied". The extended instrument was applied identically to v2 and v3. Results from the original instrument are kept alongside (`audits/verb_diversity_v3/*_original_lexicon/`).

## Exclusions

There are no new exclusions. Each eligible transformation could be produced from content available in its example, without inventing data. The 14 example exclusions from v2 are unchanged: 8 redundant duplicates, 3 pending subject-matter-expert review (429, 445, 477) and 3 flagged in the self-containment audit. They are listed in `EXCLUSION_REGISTER_v3.csv` together with the one row removed after the 252 relabel. The 245 `label_and_generation_only` examples keep that status: their rewrites are valid for Bloom-label prediction and rewriting, but not for answer scoring, and the loader still enforces this.

## Recommended human review before training

1. A random sample of the 1,378 rewritten rows, about 10% stratified by level, checked for faithfulness to the source and for Bloom alignment.
2. 252 (relabelled) and 157 (kept as Analyze).
3. The 7 Understand rows flagged as possibly needing higher-level work, and the 72 Apply rows without a concrete case.
4. The six allowlisted number exceptions (in `scripts/apply_repairs.py`, `ACCEPTED_NUMBERS`).
5. The three pending-SME examples (429, 445, 477). They remain excluded.
